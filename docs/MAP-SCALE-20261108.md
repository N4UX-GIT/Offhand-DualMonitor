# Map scale settings investigation, 2026-11-08

Status: source candidate, automated checks passed. Not packaged, installed or
accepted in the native client during this investigation.

## Report and source findings

The user reports CurseForge Beta 27, Forever, mouse/keyboard UI, and scaling
controls ineffective on Offhand and Mainhand. OpenMap was personally confirmed;
the latest side clarification does not explicitly identify which map owner was
tested. Native Blizzard reproduction, exact reporter build and enabled competing
addons remain unconfirmed.

The published Beta 27 options code matches the affected setting path in this
checkout: its slider always writes workspaceMapScale, while native Mainhand
presentation reads mainMapScale. Existing workspace scaling passes simulations;
there is no demonstrated source failure for an unowned native workspace map.
Leatrix Maps, MoveAny and ClassicUIForever remain external owners.

Offhand yields map scaling to OpenMap, whose own Hold hook restores windowScale.
Leaving an active Offhand slider that only writes workspaceMapScale cannot change
that owner preference. Auto Fit also wrote AUTO, then called Slider:SetValue,
which invoked the numeric setter and discarded the automatic mode. Same-value
presets could fail to select an explicit value after AUTO.

## Candidate

Core/MapScale.lua provides guarded explicit actions and a read-only UI state.
Native actions select the same saved-side/physical-side classification as the
existing presentation code, set that side's preference and update only the map.
Mainhand now handles AUTO as well. Display refresh uses UpdateText and preserves
AUTO; presets explicitly select their value even when the thumb already matches.
Map slider actions no longer dispatch an unrelated full UI layout.

For reviewed OpenMap v0.7.5-beta, API major 1/version 4, matching module/DB identity
and active ownership, the action builds its existing WindowOptions descriptor
with DB-only callbacks and invokes windowScale.set. This reaches the owner's
private Apply closure without mod:Refresh or a MapCanvas data-provider rebuild.
It respects the owner's 50–160% range; 200/250% presets are disabled. AUTO becomes
a one-time fitted numeric owner preference, since OpenMap has no AUTO mode.
Its own anchor, window size and native show/drag scripts stay owned by OpenMap.
No OpenMap source patch is part of this candidate.

Combat, fullscreen, native controller UI, disabled addon and unsupported owners
refuse actions. The settings card displays localized availability/owner guidance
and disables unsupported actions. All 11 locales include the new strings.
Native fitting still caps the rendered map to the selected monitor's bounds.

## Existing-slider ownership refresh

The existing slider is reused rather than adding a second competing control.
Refresh changes its label to include OpenMap, adopts the owner's saved value and
50–160% range, and disables unsupported presets. Bounds update in the captured
step/typing/drag callbacks as well as on the native rail. ADDON_LOADED and normal
panel refresh handle detection after panel construction. No native OpenMap
slider-widget hooks are needed; the reviewed owner setting transaction remains
the action path. Refresh is read-only, cancels stale drags and discards focused
input when the range changes. Regression covers native-to-OpenMap-to-native
transition, external saved-scale changes, focus loss, stepping, typing and drag.
Source-only validation remains separate from pending native acceptance.
